# 性能基础质量测试 - 联调文档

本文档供前后端联调使用，包含前端调整汇总、联调步骤与接口示例、自测检查点、常见问题排查及接口速查。

**baseUrl 示例：** `http://localhost:3000/api`

---

## 一、前端需要做的调整（汇总）

以下 10 条与《性能基础质量测试-前端对接说明》中的摘要对应，便于逐项勾选。

| 序号 | 前端需完成项 | 勾选 |
|------|--------------|------|
| 1 | 支持创建「性能基础质量测试」任务：调用 `POST {baseUrl}/tasks/test`，body 含 `taskType: "PERFORMANCE_BASELINE_TEST"`、`platform`、`deviceId`、`appId`；可选 `config.traversalMinutes`（执行时长，分钟）。 | ☐ |
| 2 | 任务列表使用 `GET {baseUrl}/tasks`（可传 `taskType=PERFORMANCE_BASELINE_TEST`）；不仅依赖 `GET .../functional-test/tasks` 的列表展示性能任务。 | ☐ |
| 3 | 列表/详情中「测试场景」列展示接口返回的 `scenarioName`（性能任务后端会填如「性能基础质量测试(Android)」）。 | ☐ |
| 4 | 运行性能任务后**轮询** `GET {baseUrl}/tasks/{taskId}`（建议 3～5 秒一次），直到 `status` 非 `RUNNING`，再刷新列表/详情，避免长时间显示「已停止」。 | ☐ |
| 5 | 性能报告数据**仅**通过 `GET {baseUrl}/functional-test/tasks/{id}/performance-report` 获取 JSON，不把报告当静态路径使用。 | ☐ |
| 6 | 整体评估：用 `conclusion`、`issueSummary`（含 `byOperationType`）渲染结论与问题统计表/饼图。 | ☐ |
| 7 | 遍历统计：用 `traversalDurationMinutes`、`launchCount`、`clickCount`、`swipeCount`、`screenshotTimeline`；截图用 `.../performance-screenshots/{index}`。 | ☐ |
| 8 | 资源数据：用 `resourceSummary` 与 `resourceSamples` 渲染 CPU/内存/网络/温度 的汇总与曲线。 | ☐ |
| 9 | 操作详情表格：用 `operations` 数组，列映射（操作类型、操作前/后截图、响应时延、完成时延、卡顿/音视频/黑白块、维测数据）；截图列 URL 为 `.../performance-screenshots/{screenshotBeforeIndex|screenshotAfterIndex}`。 | ☐ |
| 10 | 任务详情/概览继续使用 `GET {baseUrl}/functional-test/tasks/{id}/overview`，已支持性能任务；执行日志用 `executionLog` 展示。 | ☐ |

## 二、联调步骤与接口示例

按以下顺序联调，每步给出请求示例与 200 响应关键字段。

### 1. 创建任务

- **请求**：`POST {baseUrl}/tasks/test`
- **请求体示例**：
  ```json
  {
    "taskType": "PERFORMANCE_BASELINE_TEST",
    "platform": "ANDROID",
    "deviceId": "设备ID",
    "appId": "应用ID",
    "config": "{\"traversalMinutes\": 5}"
  }
  ```
- **响应 200 示例（关键字段）**：返回任务对象，含 `id`、`taskType`、`status`（如 `PENDING`）、`scenarioName`（如「性能基础质量测试(Android)」）等。

### 2. 任务列表

- **请求**：`GET {baseUrl}/tasks?page=1&size=10&taskType=PERFORMANCE_BASELINE_TEST`
- **响应 200 示例（关键字段）**：`content` 为任务数组，每项含 `id`、`taskType`、`status`、`scenarioName`、`deviceId`、`appId` 等；分页含 `totalElements`、`totalPages`。

### 3. 运行任务

- **请求**：`POST {baseUrl}/tasks/{taskId}/run`（无请求体）
- **响应 200 示例**：后端将任务状态置为 `RUNNING`，测试在后台执行；前端应据此开始轮询单任务状态。

### 4. 轮询状态

- **请求**：`GET {baseUrl}/tasks/{taskId}`，建议每 3～5 秒请求一次。
- **响应 200 示例（关键字段）**：`status` 为 `RUNNING` 时继续轮询；为 `COMPLETED`、`FAILED`、`STOPPED` 时停止轮询并刷新列表/详情。

### 5. 取报告

- **请求**：`GET {baseUrl}/functional-test/tasks/{taskId}/performance-report`
- **响应 200 示例（关键字段）**：JSON 含 `conclusion`、`issueSummary`、`traversalDurationMinutes`、`launchCount`、`clickCount`、`swipeCount`、`screenshotTimeline`、`resourceSummary`、`resourceSamples`、`operations` 等。404 表示任务不存在、非性能任务或尚无执行结果。

### 6. 取截图

- **请求**：`GET {baseUrl}/functional-test/tasks/{taskId}/performance-screenshots/{index}`（index 从 0 起，为数字）
- **响应 200**：返回图片流（如 image/png），可直接用作 `<img src="...">`（需带 cookie 或后端允许跨域）。

## 三、联调自测检查点

| 步骤 | 预期结果 | 通过 |
|------|----------|------|
| 创建 | 调用 `POST /tasks/test` 成功，返回任务含 `id`、`scenarioName`；列表中能筛出 `taskType=PERFORMANCE_BASELINE_TEST` 的任务。 | ☐ |
| 运行 | 调用 `POST /tasks/{taskId}/run` 后，单任务或列表很快显示「运行中」（来自轮询到的 `status=RUNNING`）。 | ☐ |
| 轮询 | 运行中期间持续轮询 `GET /tasks/{taskId}`，状态从 RUNNING 变为 COMPLETED/FAILED/STOPPED 后停止轮询，列表/详情展示最新状态。 | ☐ |
| 报告 | 任务完成后访问 `GET .../performance-report` 返回 200，前端用返回的 JSON 渲染整体评估、遍历统计、资源数据、操作详情。 | ☐ |
| 操作详情 | 操作详情表格有行数据，列含操作类型、操作前/后截图、响应时延、完成时延等；截图 URL 使用 `.../performance-screenshots/{index}` 能正常显示图片。 | ☐ |
| 截图 | 时间轴或操作前/后使用的截图 URL 请求返回 200 且为图片（后端已开启按间隔截图时）。 | ☐ |

## 四、常见问题与排查

| 现象 | 可能原因 | 排查方式 |
|------|----------|----------|
| 列表里没有性能任务 | 前端只调用了 `GET .../functional-test/tasks`，该接口不包含性能任务。 | 改为使用 `GET {baseUrl}/tasks`，并传 `taskType=PERFORMANCE_BASELINE_TEST` 筛选。 |
| 点击运行后一直显示「已停止」 | 运行后没有轮询任务状态，页面展示的是旧状态。 | 在 `POST .../tasks/{taskId}/run` 成功后启动轮询 `GET {baseUrl}/tasks/{taskId}`，每 3～5 秒一次，直到 `status` 非 RUNNING。 |
| 报告没数据 / 404 | 任务尚未执行完成、或任务非性能类型、或任务 id 错误。 | 确认任务已 COMPLETED，且为性能基础质量测试任务；确认请求的 taskId 与列表/详情一致。 |
| 操作详情没有截图 | 后端未开启按间隔截图，或前端未用 `screenshotBeforeIndex`/`screenshotAfterIndex` 拼截图 URL。 | 确认后端配置 `performance.screenshot-interval-seconds > 0`；确认前端使用 `.../performance-screenshots/{screenshotBeforeIndex}` 和 `.../performance-screenshots/{screenshotAfterIndex}`。 |
| 长时测试失败 / 超时 | 执行时长较长（如 30/60 分钟），网络或后端超时、设备断开等。 | 检查设备连接、后端超时配置、执行日志；可先用较短 `traversalMinutes`（如 2）验证流程。 |
| 创建任务返回 400 | 必填参数缺失或格式错误（如 platform 非 ANDROID、deviceId/appId 为空）。 | 确认 body 含 `taskType`、`platform`、`deviceId`、`appId`；性能任务仅支持 Android；`config` 为 JSON 字符串如 `"{\"traversalMinutes\": 5}"`。 |

## 五、接口速查

| 用途 | Method | 路径 |
|------|--------|------|
| 创建性能任务 | POST | `{baseUrl}/tasks/test` |
| 任务列表（含性能） | GET | `{baseUrl}/tasks`（可传 taskType、platform、status、page、size） |
| 单任务状态/详情 | GET | `{baseUrl}/tasks/{id}` |
| 运行任务 | POST | `{baseUrl}/tasks/{taskId}/run` |
| 任务概览（含执行日志） | GET | `{baseUrl}/functional-test/tasks/{id}/overview` |
| 性能报告 JSON | GET | `{baseUrl}/functional-test/tasks/{id}/performance-report` |
| 某张截图 | GET | `{baseUrl}/functional-test/tasks/{id}/performance-screenshots/{index}` |

## 二、本次文档变更说明（任务状态与列表）

- **任务状态与前端轮询**：点击「运行」后后端立即将任务置为 RUNNING，测试在后台执行。前端在任务详情页轮询 **`GET /api/tasks/{taskId}`**（已由原 `getFunctionalTestTask` 改为 `getTask`），每 3 秒一次，状态变为 COMPLETED/FAILED/STOPPED 时停止轮询并刷新概览。
- **任务列表数据源**：**`GET /api/functional-test/tasks` 不包含性能任务**。自动化测试页任务列表已改为 **`GET /api/tasks`**（`apiClient.getTasks`），分页与 status 筛选保留；列表项统一映射为 `id/taskId、taskName、status、taskType、platform、createdAt、scenarioKey、scenarioName` 等，功能与性能任务均展示。若后端 `GET /api/tasks` 未支持按天数/关键词筛选，当前前端仅传 status 与分页参数。

## 五、前端是否需要做调整

### 「操作详情」数据如何获取（按文档对接即可）

操作详情表格数据来自性能报告 JSON 的 **`operations`** 数组，每行对应 `operations[i]`。截图使用同一任务的性能截图接口，通过**截图索引**拼 URL。

| 展示列 | 报告 JSON 字段（operations[i]） | 截图 URL 拼法 |
|--------|--------------------------------|---------------|
| **操作类型** | `type`（操作类型）；可选 `actionLabel`（操作描述）、`pageName`（页面） | — |
| **操作前** | `screenshotBeforeIndex`（截图索引，0 起） | `GET {baseUrl}/functional-test/tasks/{taskId}/performance-screenshots/{screenshotBeforeIndex}` |
| **操作后** | `screenshotAfterIndex`（截图索引） | `GET {baseUrl}/functional-test/tasks/{taskId}/performance-screenshots/{screenshotAfterIndex}` |
| **加载完成时延** | `completionDelayMs`（单位 ms） | — |
| **黑白块** | `blackWhiteBlockCount`（本步黑白块次数，可选） | — |
| **维测数据** | `dimensionData` 或后端约定的维测字段（可选） | — |

说明：

- 前端通过 `getPerformanceReport(taskId)` 获取报告 JSON，表格绑定 `performanceReport.operations`。
- 操作前/操作后截图：`img` 的 `src` 使用 `getPerformanceScreenshotUrl(taskId, row.screenshotBeforeIndex)` / `getPerformanceScreenshotUrl(taskId, row.screenshotAfterIndex)`，即上述 GET 拼法。
- 若某字段后端暂未返回，前端展示为「—」或留空；后端扩展字段后前端按上表补充列即可。

#### 为什么操作详情没有截图？

按下面三点排查即可：

| 检查项 | 说明 |
|--------|------|
| **1. 是否开启按间隔截图** | 配置 `performance.screenshot-interval-seconds` 必须**大于 0**（例如 1）。为 0 时不会截屏，screenshotTimeline 为空，所有 screenshotBeforeIndex / screenshotAfterIndex 都是 null，前端自然没有图。 |
| **2. 前端是否用索引拼图片地址** | 「操作前」「操作后」必须用接口返回的 `screenshotBeforeIndex`、`screenshotAfterIndex` 拼出图片 URL：`GET {baseUrl}/functional-test/tasks/{任务id}/performance-screenshots/{index}`（注意 baseUrl 通常含 `/api`）。用 `<img src="该URL">` 展示；为 null 时显示占位或「无」。 |
| **3. 任务 ID 与报告是否一致** | 截图接口按「任务 id」读该任务最新一次执行的截图；前端要用**同一任务的 id** 请求 performance-report 和 performance-screenshots/{index}，否则会 404 或看不到图。 |

建议先确认：application.yml 里是否有 `performance.screenshot-interval-seconds: 1`（或其它大于 0 的值）；前端操作详情表格里「操作前」「操作后」是否用 `operations[i].screenshotBeforeIndex` / `screenshotAfterIndex` 拼成上述 GET URL 并作为 `<img src="...">` 的地址。按文档这三点对上了，操作详情就会和参考截图一样有图。

## 六、结论

- 前端已按《性能基础质量测试-实现说明》完成对接，**无需再改**。

# 设备管理接口说明（给前端）

用于「设备管理」页的**设备列表**展示与操作。后端 `context-path` 为 `/api`，基址示例：`http://localhost:3000/api`。

---

## 一、获取设备列表（必接）

| 项目 | 值 |
|------|-----|
| **方法** | `GET` |
| **URL** | `{baseUrl}/devices` |

**响应：** 设备对象数组。字段：id、name、platform（ANDROID/IOS/HARMONYOS）、version、status（CONNECTED/DISCONNECTED）、lastSeen、config。

---

## 二、刷新设备列表（可选）

| 项目 | 值 |
|------|-----|
| **方法** | `POST` |
| **URL** | `{baseUrl}/devices/scan` |

调用后再次请求 `GET {baseUrl}/devices` 即可得到最新列表。

---

## 三、按平台筛选设备（可选）

| 项目 | 值 |
|------|-----|
| **方法** | `GET` |
| **URL** | `{baseUrl}/devices/platform/{platform}` |
| **platform** | `ANDROID` / `IOS` / `HARMONYOS` |

---

## 四、连接 / 断开设备（可选）

- **连接**：`POST {baseUrl}/devices/{id}/connect`
- **断开**：`POST {baseUrl}/devices/{id}/disconnect`

---

## 五、设备详情（点击设备后展示）

点击「总量」或表格里某台设备时请求此接口，用返回数据展示详情弹窗。

| 项目 | 值 |
|------|-----|
| **方法** | `GET` |
| **URL** | `{baseUrl}/devices/{设备id}/detail` |
| **示例** | `http://localhost:3000/api/devices/6HJDU20409003857/detail` |

**请求参数：** 路径参数为设备 `id`。

**响应：** `200` 为成功，JSON 对象；`404` 表示设备不存在或无效。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 设备 ID |
| name | string | 设备名称 |
| platform | string | ANDROID / IOS / HARMONYOS |
| version | string | 系统版本 |
| status | string | CONNECTED / DISCONNECTED |
| batteryLevel | number \| null | 电量 0–100，无数据时为 null |
| installedApplications | array | 已安装应用列表，每项含 name、packageName、version |
| iosDetail | object | 仅当 platform === 'IOS' 时存在，解析后的键值对（表格/列表用） |
| iosDetailRaw | string | 仅 iOS：ideviceinfo 的完整标准输出（多行文本），用 `<pre>` 原样展示 |
| androidDetail | object | 仅当 platform === 'ANDROID' 或 'HARMONYOS' 时存在，分层结构（表格/列表用） |
| androidDetailRaw | string | 仅 Android/HarmonyOS：getprop 全量 + dumpsys battery 的完整输出（多行文本），用 `<pre>` 原样展示 |

**iosDetail 常见键（仅 iOS）：** DeviceName、ProductName、ProductVersion、SerialNumber、UniqueDeviceID、CarrierName、设备储存相关字段等。

**androidDetail 结构（仅 Android/HarmonyOS）：** 各子对象均为键值对，部分键可能为空。

| 子对象 | 说明 | 常见键示例 |
|--------|------|------------|
| systemInfo | 系统与设备身份 | serialNumber、Android ID、versionRelease、sdkInt、securityPatch、buildType、brand、model、manufacturer、board、hardware、bluetoothDeviceName 等 |
| hardwareInfo | 硬件配置 | screenSize、screenDensity、CPU ABI、cpuCores、memTotal、memAvailable |
| batteryInfo | 电池 | level、status、temperature、voltage、health、charging |
| storageInfo | 存储 | 总/已用/可用块数等（前端可换算为容量） |
| networkInfo | 网络与连接 | WiFi SSID、WiFi IP、网络类型、NFC、定位等 |
| securityInfo | 安全与调试 | adb 是否开启、buildTags、bootloader 是否解锁、是否 root |
| sensorInfo | 传感器 | 加速度计、陀螺仪、指纹等（true/false） |

**前端展示建议：**
- 设备名称、电量（batteryLevel 显示为「xx%」，null 显示「电量未知」）。
- 已安装应用：表格列用 installedApplications[].name / packageName / version。
- 仅当 platform === 'IOS' 时展示 iosDetail 区块（名称、型号、操作系统、序列号、UDID、运营商、储存等）。
- 仅当 platform === 'ANDROID' 或 'HARMONYOS' 时展示 androidDetail：按区块展示「系统基础信息」「硬件配置」「电池」「存储」「网络与连接」「安全与权限」「传感器」，各层键值对用表格或列表展示。
- **完整原始数据**：增加一块「设备信息完整输出」，用 `response.iosDetailRaw`（iOS）或 `response.androidDetailRaw`（Android/HarmonyOS）在 `<pre class="device-info-raw">` 中原样展示，不丢行。若 iosDetail 为空但设备为 iOS，仍可只展示 iosDetailRaw。
- 接口返回 404 时提示「设备不存在或无效」。

---

## 六、前端对接要点

1. 进入「设备管理」页请求 `GET {baseUrl}/devices`，表格列：设备名称(name)、平台(platform)、版本(version)、状态(status)、操作。
2. 状态展示：`CONNECTED` → 已连接，`DISCONNECTED` → 未连接。
3. 列表为空时：可调用 `POST {baseUrl}/devices/scan` 触发扫描，再请求 `GET {baseUrl}/devices`。
4. 点击表格中某台设备（或「总量」等入口）时请求 `GET {baseUrl}/devices/{id}/detail`，在弹窗中展示设备名称、电量、已安装应用列表；若为 iOS 则展示 iosDetail 详细设备信息。404 时提示「设备不存在或无效」。

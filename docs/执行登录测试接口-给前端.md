# 执行登录自动化测试 - 接口说明（给前端）

## 接口信息

| 项目 | 值 |
|------|-----|
| **方法** | `POST` |
| **URL** | `{baseUrl}/functional-test/execute` |
| **Content-Type** | `application/json` |

**说明：** `baseUrl` 为后端 API 根路径，例如 `http://localhost:3000/api`（端口以实际为准，路径必须包含 `/api`）。

**完整示例 URL：** `http://localhost:3000/api/functional-test/execute`

**后端执行说明（先启动应用，再执行登录测试）：**  
接口会创建任务并提交异步执行。执行流程：**先通过 Appium WebDriver 创建会话并启动应用**（`driver.launchApp`），**再执行登录步骤**（点击、输入、截图等）。当 **`appium.enabled=true`**（默认）时，驱动为 Appium WebDriver，会连接 Appium Server 启动应用并完成自动化登录；若 Appium 服务常驻，请保持 **`appium.enabled: true`**。若设为 false，则用 ADB/idevice 启动应用，登录步骤能力会受限。

---

## 请求体（RequestBody）

```json
{
  "scenarioId": "login_android",
  "deviceId": "设备ID",
  "applicationId": "应用ID",
  "config": "{\"phoneNumber\":\"12312340002\",\"verificationCode\":\"521758\"}"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| scenarioId | string | 是 | Android 填 `login_android`，iOS 填 `login_ios` |
| deviceId | string | 是 | 设备 ID（从设备列表接口获取） |
| applicationId | string | 是 | 应用 ID（从「该设备下的应用列表」接口中，每个应用的 `id` 字段获取，不是设备 ID） |
| **config** | string | 否 | **登录测试参数（推荐前端必传）**。JSON 字符串，包含 `phoneNumber`、`verificationCode`。多部手机时每次执行由前端传不同手机号/验证码，无需改后端代码。未传时使用后端默认值。 |

**config 示例（推荐每次执行由前端传入）：**
- 手机号：`phoneNumber`，如 `"12312340002"`
- 短信验证码：`verificationCode`，如 `"521758"`
- 完整 config 字符串：`"{\"phoneNumber\":\"12312340002\",\"verificationCode\":\"521758\"}"`

---

## 响应（200 成功）

```json
{
  "taskId": "任务UUID",
  "status": "RUNNING",
  "message": "任务已提交执行"
}
```

- **taskId**：后续可用 `GET {baseUrl}/tasks/{taskId}` 轮询任务状态。
- **status**：如 PENDING、RUNNING、COMPLETED、FAILED。
- **message**：提示信息。

---

## 错误情况

- **400**：缺少或非法参数（如 scenarioId/deviceId/applicationId 为空、或 scenarioId 不在支持范围内）。请求体可能无返回或简单错误信息。
- 前端需保证：三个必填字段非空；**applicationId** 必须是「应用」的 id，不能是设备 id。

---

## curl 示例（替换实际值后可直接在终端测试）

```bash
# 带登录参数（手机号、验证码由前端/调用方传入，多机时每次传不同值）
curl -X POST "http://localhost:3000/api/functional-test/execute" \
  -H "Content-Type: application/json" \
  -d '{"scenarioId":"login_android","deviceId":"你的设备ID","applicationId":"你的应用ID","config":"{\"phoneNumber\":\"12312340002\",\"verificationCode\":\"521758\"}"}'
```

---

## 前端自检清单

1. 请求方法是否为 **POST**。
2. URL 是否为 **`{baseUrl}/functional-test/execute`**（baseUrl 含 `/api`）。
3. 请求头是否包含 **`Content-Type: application/json`**。
4. Body 是否为 JSON，且字段名为 **scenarioId**、**deviceId**、**applicationId**（驼峰，注意是 application**Id**）。
5. **applicationId** 是否来自「该设备下应用列表」里某一项的 **id**，而不是设备 ID 或其它值。
6. **登录测试**：是否通过 **config** 传入当次执行的 **phoneNumber**、**verificationCode**（多部手机时每次传不同值，无需改后端）。

# 停止当前自动化测试 - 接口说明

## 接口信息

| 项目 | 值 |
|------|-----|
| **方法** | `POST`（注意是 POST，不是 GET） |
| **URL** | `{baseUrl}/tasks/{taskId}/stop` |

**说明：** `taskId` 为任务 ID（列表/详情中的任务 id）；`baseUrl` 为 API 根路径，例如 `http://localhost:3000/api`（必须含 `/api`）。

**完整示例 URL：** `http://localhost:3000/api/tasks/这里填taskId/stop`

**前端注意：** 若出现「Network error」，请检查：1）请求方法是否为 **POST**；2）URL 是否为 **{baseUrl}/tasks/{任务ID}/stop**（baseUrl 含 `/api`）。只要任务存在，后端会返回 **200** 并将任务标记为已停止。

---

## 请求

- **无请求体**，只需在 URL 中传入要停止的任务 ID。

---

## 响应

- **200**：停止成功（任务进程已被终止，任务状态会更新为 STOPPED）。
- **400**：停止失败（例如该任务当前并未在运行、或任务已结束）。

---

## curl 示例

```bash
curl -X POST "http://localhost:3000/api/tasks/你的taskId/stop"
```

# 删除任务 - 接口说明

## 接口信息

| 项目 | 值 |
|------|-----|
| **方法** | `DELETE` |
| **URL** | `{baseUrl}/tasks/{taskId}` |

**说明：** 删除时后端会**先停止任务**（若正在运行），再删除任务及关联执行记录。前端只需调用本接口一次即可。

**完整示例 URL：** `http://localhost:3000/api/tasks/这里填taskId`

---

## 请求

- **无请求体**，URL 中传入要删除的任务 ID。

---

## 响应

- **200**：删除成功（已先停止再删除）。
- **404**：任务不存在。

---

## curl 示例

```bash
curl -X DELETE "http://localhost:3000/api/tasks/你的taskId"
```

# 五、测试任务列表（按截图方式：筛选 + 卡片展示）

**接口：** `GET {baseUrl}/functional-test/tasks`

**可选查询参数（与截图中的筛选对应）：**

| 参数 | 类型 | 说明 |
|------|------|------|
| **days** | number | 时间范围：不传或 0=全部，3=近三天，7=近一周 |
| **keyword** | string | 任务名或备注关键词（模糊搜索） |
| **status** | string | 任务状态：COMPLETED（完成）、STOPPED（停止）、RUNNING（运行中）、PENDING、FAILED 等 |

**示例：**
- 全部：`GET /api/functional-test/tasks`
- 近三天：`GET /api/functional-test/tasks?days=3`
- 近一周：`GET /api/functional-test/tasks?days=7`
- 仅完成：`GET /api/functional-test/tasks?status=COMPLETED`
- 搜索：`GET /api/functional-test/tasks?keyword=登录`

**响应每条任务含：** id、taskName、remarks、platform、deviceId、applicationId、**deviceName**（设备名称，便于卡片展示）、status、createdAt、executionStatus、reportPath、errorMessage、executionEndTime。

前端可据此做卡片布局：任务 ID（id）、状态（status/executionStatus）、测试服务（taskName）、设备名称（deviceName）、创建时间（createdAt）、备注（remarks），并配合「删除报告」调用 `DELETE /api/tasks/{id}`。

# 六、小结与前端对接流程

| 操作 | 接口 | 说明 |
|------|------|------|
| **执行登录测试** | `POST {baseUrl}/functional-test/execute` | Body 含 scenarioId、deviceId、applicationId、**config**（手机号、验证码）。 |
| **轮询任务结果** | `GET {baseUrl}/functional-test/tasks/{taskId}` | 用 executionStatus、reportPath、errorMessage 展示结果。 |
| **停止测试** | `POST {baseUrl}/tasks/{taskId}/stop` | 无请求体。 |
| **删除任务** | `DELETE {baseUrl}/tasks/{taskId}` | 后端先停止再删除，前端只调一次。 |
| **任务列表（筛选）** | `GET {baseUrl}/functional-test/tasks?days=3&status=COMPLETED&keyword=xx` | 支持全部/近三天/近一周、状态、关键词；返回含 deviceName。 |

**删除任务对接流程：**

1. 用户点击「删除」某条任务（列表或详情页）。
2. 前端调用 **DELETE {baseUrl}/tasks/{taskId}**（无需先调停止）。
3. 若返回 200，从列表移除该任务或跳转列表；若 404，提示任务不存在。
